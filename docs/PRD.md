# PRD: 중장년층 마음기록카드 펫 앱 (MVP 웹앱 프로토타입)

> 이 문서는 Claude Code가 프로토타입을 구현하기 위한 명세입니다. 데모데이 시연용이며, 아래 "범위 밖" 항목은 구현하지 마세요.

## 0. 한 줄 요약

병원에서 안내받아 쓰는 **디지털 마음기록카드**. 사용자는 매일 질문 1개("오늘 무엇을 드셨나요?")에 사진 또는 음성으로 답하고, 강아지에게 밥을 주면 그날의 **기록 카드**가 앨범에 쌓인다. 진료 때 환자가 앨범 화면을 의료진에게 직접 보여준다.

## 1. 포지셔닝 (반드시 지킬 선)

- 진료를 돕는 **자기기록 보조 도구**이다. 진단, 치료, 모니터링, 응급 대응을 하지 않는다.
- 답변을 **분석·점수화·요약·상태 판정하지 않는다.** (의료기기 해당 이슈 방지)
- 의료진은 실시간으로 기록을 보지 않는다. 환자가 진료 때 앱 화면을 직접 보여준다.
- 앱 안의 모든 문구에서 "치료", "치료 효과", "우울증 개선" 같은 표현을 쓰지 않는다.
- 앱은 진단명을 묻지 않는다.

## 2. 타깃 사용자와 UI 원칙

- 65세 전후, 혼자 사는 사용자. 카카오톡과 사진 촬영 정도의 기본 스마트폰 사용 가능.
- 데모 단계 체험자는 지인·가족 3~5명.
- **UI 원칙**
  - 큰 글씨 (본문 최소 20px 이상, 버튼 글씨 22px 이상 권장)
  - 큰 터치 영역 (버튼 높이 56px 이상)
  - 한 화면에 한 가지 행동만
  - 짧은 문장, 존댓말, 아이를 대하는 말투는 피함
  - 높은 명암 대비, 모바일 세로 화면 우선 (데스크톱에서도 열리되 폭은 모바일 폭으로 제한해도 됨)
  - 한국어 UI

## 3. 기술 방향

- **웹앱** (링크로 접속, 앱스토어 배포 없음). 서버·계정·DB 없음. **모든 데이터는 브라우저 안에만 저장**한다.
- 스택은 Claude Code가 가볍게 선택하되, 기본 제안은 다음과 같다.
  - Vite + React(또는 순수 HTML/JS), 모바일 우선 CSS
  - 저장: **IndexedDB** (사진·음성 Blob 저장용). 설정·간단한 값은 localStorage 가능
  - 녹음: `MediaRecorder` API. 사진: `<input type="file" accept="image/*" capture>` 또는 `getUserMedia`
  - 애니메이션: CSS 애니메이션 또는 GIF/스프라이트 (복잡한 라이브러리 불필요)
  - 배포: Vercel 등 HTTPS 제공 서비스 (마이크·카메라는 HTTPS에서만 동작)
- **브라우저 호환:** 아이폰 Safari와 안드로이드 Chrome에서 동작해야 한다.
  - Safari는 `audio/mp4`(m4a) 계열, Chrome은 `audio/webm`으로 녹음된다. `MediaRecorder.isTypeSupported()`로 지원 형식을 확인해 선택하고, 저장 시 mimeType을 함께 기록해 재생 시 그대로 사용한다.
  - 효과음 재생은 브라우저 자동재생 정책 때문에 **사용자 터치 이후**에만 가능하다. 밥 주기 버튼 터치 시점에 재생한다.
- 사진은 저장 전에 긴 변 기준 1280px 정도로 리사이즈해서 저장 용량을 줄인다.
- 오프라인 동작이나 PWA 설치는 필수가 아니다.

## 4. 화면 구성

| # | 화면 | 설명 |
|---|---|---|
| 1 | 동의 화면 | 첫 실행 시에만 표시. 한 화면에 한 가지씩 여러 단계 |
| 2 | 간이 프로필 | 이름 또는 별명 1개 입력 (연령대 선택은 선택 사항) |
| 3 | 홈 | 강아지, 오늘의 질문, "답하기" 버튼, 앨범 이동, 설정 이동 |
| 4 | 답변 화면 | 사진 찍기/고르기 또는 음성 녹음, 건너뛰기 |
| 5 | 밥 주기·반응 화면 | 밥 주기 버튼 → 강아지 애니메이션 → 말풍선 → 레벨 표시 |
| 6 | 기록 앨범 | 카드 목록 (최신이 위) |
| 7 | 카드 상세 | 카드 크게 보기, 음성 재생 |
| 8 | 설정 | 안전 문구, 109 전화 버튼, 내 기록 모두 지우기, 개인정보 처리방침 |

### 4-1. 동의 화면 (첫 실행)

한 화면에 한 가지씩, "다음" 버튼 하나로 진행한다. 마지막 화면에 "동의합니다" 버튼 1개와 "동의하지 않아요" 버튼 1개를 둔다.

1. 이 앱이 무엇인지: 진료를 돕는 마음기록카드이며, 진단·치료·응급 대응을 하지 않음
2. 모으는 것: 음성 녹음, 사진, 이름(별명)
3. 쓰는 목적: 기록 앨범 제공, 진료 때 본인이 직접 확인
4. 보관과 삭제: 기록은 이 기기의 브라우저 안에만 저장되고 서버로 보내지지 않음. 설정에서 언제든 모두 지울 수 있음. **브라우저 데이터를 지우거나 다른 기기로 열면 기록이 보이지 않음**
5. 안전 안내(아래 안전 문구)
6. 동의하지 않아도 불이익이 없음. "동의하지 않아요"를 누르면 "앱을 사용하지 않으셔도 괜찮아요" 안내 후 종료 화면 (데이터 저장 없음)

동의 여부와 동의 시각은 localStorage에 저장하고, 동의 후에는 다시 보여주지 않는다.

### 4-2. 안전 문구 (정적 텍스트)

동의 화면(5단계)과 설정 화면에 아래 문구를 그대로 표시한다.

> 이 앱은 의료진이 실시간으로 보지 않으며 응급 대응을 하지 않습니다. 많이 힘드실 때는 자살예방상담전화 109, 위급할 때는 119, 담당 병원으로 연락해 주세요.

- 설정 화면에 **"109 전화하기" 버튼** 1개 (`<a href="tel:109">`).
- 번호 상수는 한 곳(`constants`)에 모아두어 배포 전 쉽게 확인·수정할 수 있게 한다.
- 위기 감지, 위기 분기 화면, 항상 보이는 도움 버튼은 **구현하지 않는다.**

### 4-3. 홈

- 강아지가 기다리는 모습(기본 대기 애니메이션: 숨쉬기/꼬리 살랑)
- 오늘의 질문 텍스트
- 오늘 이미 기록했다면: "오늘의 기록을 마쳤어요" 상태로 표시하고 답하기 버튼은 비활성 또는 숨김. 앨범으로 가는 버튼 강조
- 오늘 아직이면: 큰 "답하기" 버튼
- 하단/상단에 앨범, 설정 이동 버튼 (큰 터치 영역)
- 친밀도 레벨 표시는 간단하게 (예: "친밀도 Lv.3")

### 4-4. 답변 화면

- 선택지 3개: **사진 남기기**, **음성으로 말하기**, **오늘은 건너뛰기**
- 사진: 카메라 촬영 또는 갤러리 선택 → 미리보기 → "이 사진으로 할게요" / "다시 고르기"
- 음성: 녹음 시작 버튼 → 녹음 중 표시(경과 시간, 큰 정지 버튼) → 정지 후 들어보기 → "이대로 할게요" / "다시 녹음". 최대 녹음 시간 60초, 도달 시 자동 정지
- 답변은 사진 1장 **또는** 음성 1개 (하루 1건, 둘 중 하나)
- 건너뛰기: 카드·포인트·밥 없이 홈으로 돌아감. 어떤 부정적 문구도 표시하지 않음
- **오류 처리 (쉬운 말):**
  - 마이크/카메라 권한 거부: "마이크를 사용할 수 없어요. 사진으로 남기시거나, 설정에서 마이크를 허용해 주세요." (권한 허용 방법을 간단히 안내)
  - 녹음/촬영/저장 실패: "잘 저장되지 않았어요. 다시 한 번 해볼까요?" + 다시 시도 버튼
  - 어떤 오류에서도 사용자를 탓하는 표현을 쓰지 않는다

### 4-5. 밥 주기·반응 화면

답변이 저장되면 이 화면으로 이동한다.

1. "오늘의 밥이 도착했어요" 표시 + 큰 **"밥 주기"** 버튼
2. 버튼 터치 시: 강아지가 밥을 먹는 애니메이션(꼬리 흔들기) + 멍멍 효과음
3. 친밀도 포인트 +1 적립, 레벨 상승 시 레벨 표시 갱신
4. **고정 문구 3개 중 랜덤** 말풍선 표시
   - "오늘 와줘서 고마워요. 멍!"
   - "이야기해줘서 고마워요. 멍!"
   - "오늘도 만나서 반가워요. 멍!"
5. "기록 카드가 앨범에 저장됐어요" 안내 + "앨범 보기" / "홈으로" 버튼

- 말풍선은 답변 내용을 해석하거나 평가하지 않는다. 위 3개 외 문구를 추가하지 않는다.
- 친밀도 레벨 규칙: 포인트 3점마다 레벨 +1 (단순 계산, 상수로 분리해 쉽게 조정). 포인트는 **쌓기만 하고 절대 줄지 않는다.**

### 4-6. 기록 카드와 앨범

**카드 = 하루 한 건**

| 요소 | 내용 |
|---|---|
| 날짜 | 큰 글씨, 예: "10월 4일 일요일" (연도는 상세에서 표시 가능) |
| 질문 | 그날의 질문 텍스트 |
| 답변 | 사진 썸네일 또는 음성 재생 버튼 |
| 강아지 | 모든 카드에 **동일한 강아지 이미지 1종** |

**앨범 화면**
- 카드를 날짜순(최신이 위)으로 목록 표시
- 카드를 누르면 상세(사진 크게 보기 / 음성 재생·정지)
- **건너뛴 날은 카드도, 빈 칸도, 안내 문구도 표시하지 않는다.**
- 카드가 아직 없을 때만 "아직 기록이 없어요. 오늘 첫 기록을 남겨볼까요?" 같은 중립 문구 표시
- 카드 편집, 개별 삭제, 공유, 내보내기, 인쇄 기능 없음 (진료 때는 앱 화면을 그대로 보여줌)

### 4-7. 설정

- 안전 문구 + "109 전화하기" 버튼
- **"내 기록 모두 지우기"** 버튼: 확인 대화상자("모든 기록이 지워지고 되돌릴 수 없어요. 지울까요?") 후 IndexedDB·localStorage의 모든 앱 데이터 삭제 (카드, 포인트, 프로필, 동의 상태 포함) 후 첫 화면으로 이동
- 개인정보 처리방침: 앱 안에서 열리는 한 페이지 (내용은 아래 5-4 참고)
- 이름(별명) 수정은 선택 사항

## 5. 데이터와 콘텐츠

### 5-1. 데이터 모델 (브라우저 내 저장)

```
profile   { name: string, ageGroup?: string }
consent   { agreed: boolean, agreedAt: ISO string }
pet       { points: number }   // level은 points로부터 계산
cards[]   {
  id: string,
  date: "YYYY-MM-DD",          // 기기 로컬 날짜 기준, 하루 1건
  questionId: string,
  questionText: string,
  answerType: "photo" | "voice",
  answerBlob: Blob,
  mimeType: string,
  createdAt: ISO string
}
```

- 하루에 카드는 최대 1건. 이미 있는 날짜에는 새 답변을 받지 않는다.
- 날짜 판단은 기기 로컬 시간 기준이며, 자정이 지나면 새 질문이 열린다.
- 서버 전송, 외부 분석 도구, 광고, 쿠키 추적을 넣지 않는다.

### 5-2. 질문 세트 (초안 12개, JSON 파일로 분리)

식사·날씨·산책·오늘 본 것 등 가벼운 일상 질문만 사용한다. 증상·기분·수면 점검형 질문, 과거 회상·상실을 건드릴 수 있는 질문은 넣지 않는다.

1. 오늘 무엇을 드셨나요?
2. 오늘 아침(또는 점심)에는 어떤 음식을 드셨나요?
3. 오늘 하늘은 어땠나요?
4. 오늘 창밖으로 무엇이 보이나요?
5. 오늘 집 근처에서 본 것 중 하나를 남겨볼까요?
6. 오늘 마신 차나 음료가 있나요?
7. 오늘 입은 옷을 남겨볼까요?
8. 오늘 산책을 하셨다면 어디까지 가셨나요?
9. 오늘 집 안에서 가장 마음에 드는 곳은 어디인가요?
10. 오늘 본 꽃이나 나무가 있나요?
11. 오늘 들은 소리 중 기억에 남는 것이 있나요?
12. 오늘 하루를 한 장의 사진으로 남겨볼까요?

- 질문 선택: 날짜 기반으로 순환 (예: 시작일로부터 경과 일수 % 질문 수). 같은 날에는 항상 같은 질문이 보인다.
- 문구는 데모 전에 사람이 한 번 더 검수한다.

### 5-3. 펫 에셋

- 강아지 대기, 밥 먹기(꼬리 흔들기), 반갑게 달려오기 애니메이션: 우선 **플레이스홀더**(간단한 SVG/이모지 기반 또는 CSS 애니메이션)로 구현하고, 이후 AI 생성 이미지/GIF로 교체할 수 있게 에셋 경로를 한 곳에 모은다.
- 멍멍 효과음: 짧은 무료 효과음 파일 1개 (플레이스홀더 허용). 라이선스를 확인한다.
- 카드용 강아지 이미지 1종.

### 5-4. 개인정보 처리방침 (한 페이지, 쉬운 문장)

- 수집 항목: 음성, 사진, 이름(별명)
- 목적: 기록 앨범 제공, 본인이 진료 때 확인
- 보관: 이 기기의 브라우저 안에만 저장, 서버로 전송하지 않음, 개발자가 볼 수 없음
- 삭제: 설정의 "내 기록 모두 지우기" 또는 브라우저 데이터 삭제
- 제3자 제공 없음
- (프로토타입 문구이며, 정식 출시 전 법률 검토 필요 — 이 문장은 개발 문서에만 두고 앱 화면에는 넣지 않아도 됨)

## 6. 핵심 사용자 흐름

1. 첫 접속 → 동의 → 이름 입력 → 홈
2. 홈에서 오늘의 질문 확인 → "답하기"
3. 사진 또는 음성으로 답변 → 미리보기/들어보기 → 확정
4. 밥 주기 → 강아지 반응 + 랜덤 말풍선 + 레벨 반영
5. 카드 저장 → 앨범에서 확인

**결석 시 (중요):** 며칠 빠진 뒤 다시 열어도 부정적 연출은 일절 없다. 강아지가 반갑게 달려오며 꼬리를 흔든다. 허용: "다시 만나서 반가워요" 류의 따뜻한 인사. 금지: 배고파함, 슬퍼함, 레벨 하락, "왜 안 왔어요" 문구, 연속 접속 일수 표시, 빠진 날 표시.

## 7. 범위 밖 (구현하지 말 것)

- 회원가입, 본인인증, 로그인
- 서버 저장, 백업, 계정 연동, 지표 자동 수집, 분석 도구
- 위기 키워드 감지, 자동 알림, 위기 분기 화면, 항상 보이는 도움 버튼, 답변 후 기분 체크, 보호자·의료진 알림
- 답변 내용에 반응하는 맞춤형 말풍선(LLM), 말풍선 문구 확장
- 음성 텍스트 변환, 사진/음성 내용 분석, 식사 패턴 분석, 점수, 요약, 감정 스티커
- 의료진용 화면, 병원 시스템·EMR 연동, 복약 알림
- 카드 편집·개별 삭제, 공유·내보내기·인쇄, 카드별 다른 장식 이미지
- 푸시 알림, 앱스토어 배포, PWA 설치 유도
- 강아지 성장·옷·꾸미기·상점, 커뮤니티·친구·산책, 다중 캐릭터

## 8. 인수 기준 (데모 전 확인 체크리스트)

- [ ] 아이폰 Safari와 안드로이드 Chrome 양쪽에서 사진 답변 → 밥 주기 → 카드 저장 → 앨범 확인이 오류 없이 끝난다
- [ ] 양쪽에서 음성 녹음·재생이 된다 (Safari m4a, Chrome webm)
- [ ] 마이크/카메라 권한을 거부해도 앱이 멈추지 않고 쉬운 안내가 나온다
- [ ] 새로고침하거나 브라우저를 껐다 켜도 카드·포인트·프로필이 유지된다
- [ ] 같은 날 두 번째 답변은 받지 않는다 (홈에서 완료 상태 표시)
- [ ] 건너뛰기 시 카드·포인트가 생기지 않고 부정적 문구가 없다
- [ ] 며칠 뒤 다시 열어도 부정적 연출·연속일수·빠진 날 표시가 없다
- [ ] 말풍선이 3개 문구 중 랜덤으로 나온다
- [ ] 동의 화면, 설정 화면에 안전 문구가 있고 109 버튼이 전화 앱을 연다
- [ ] "내 기록 모두 지우기"가 모든 데이터를 지우고 첫 화면으로 돌아간다

## 9. 데모데이 시연 순서

1. 첫 접속 화면과 동의 화면 (안전 문구 포함) 간단히 소개
2. 질문 확인 → 사진 답변 → 밥 주기 → 강아지 반응·말풍선 → 카드 저장
3. 앨범에서 카드 확인 (진료 때 이렇게 보여준다는 설명)
4. 설정 화면의 109 버튼, 전체 삭제 기능 소개
5. 설명 멘트: "지금은 컨셉과 사용성 검증 단계이고, 병원 연계 검증(환자 5~10명, 2~4주)은 다음 단계입니다."

## 10. 데모 이후 단계 (참고, 구현 대상 아님)

- 병원 연계 환자 대상 검증: 5~10명, 2~4주, "7일 중 5일 이상 기록" 50% 이상을 목표 가설로 둠
- 필요 절차: 병원 협의, IRB 심의, 식약처/의료기기안전정보원 의료기기 해당 여부 문의, 개인정보 처리방침 법률 검토
- 이후 가설: 고립감 완화 (MVP에서 검증하지 않음), 내용 반응형 말풍선, 서버 저장, 위기 감지
